# TS 최종 방향 (2026-09-07 확정)

> AI Championship 2026 제출용. 참가신청 마감 9/18 23:59:59, 과제 제출 마감 9/20 23:59:59.

## 1. 컨셉

기존 TS: POS 엑셀 업로드 → 재무지표 → 그래프 → 개선방안

**수정할 TS**: POS·매입 데이터를 업로드하면 AI가 매장의 문제와 놓치고 있는 금전적
기회를 찾아 "지금 무엇을 하면 얼마가 달라지는지" 알려주는 서비스.

두 개의 엔진 + 시뮬레이터 구조:

| 엔진 | 역할 |
|---|---|
| AI 경영진단 | 매출·원가·인건비·고정비·순이익 문제 탐지 |
| Opportunity Finder | 절세·공제·비용절감 등 놓친 기회 탐지 |

두 엔진의 결과를 **Action Simulator**로 마지막에 합친다.

## 2. 화면 구성 (5개)

### 화면 ① 사업자 정보 + 데이터 업로드
- 기존 엑셀 업로드 화면 유지
- 처음 한 번만 사업자 기본정보 추가 입력: 사업자 유형, 과세 유형, 업종, 전년도 매출, 분석기간
- POS/매입 데이터 업로드
- **[샘플 데이터로 체험하기]** 버튼 필수 (심사위원 데모용 — 매우 중요)

### 화면 ② 경영 현황
- 경영 건강점수 (100점 만점)
- KPI 4~5개: 매출, 영업비용, 순이익, 영업이익률, 손익분기점
- 그래프 여러 개 나열 금지 — 바로 아래에 "AI가 발견한 가장 중요한 변화" 1개 (첫 번째 WOW 포인트)
  - 예: "매출보다 비용 증가가 문제입니다. 순이익 감소의 약 68%가 인건비 증가에서 발생했습니다."

### 화면 ③ AI 경영진단
- 정확히 3개만: 🔴 인건비 부담 / 🟠 원재료비 상승 / 🟢 객단가 개선 (예시)
- **원칙: AI는 숫자를 만들지 않는다.** 모든 수치는 코드가 계산, AI는 "무엇이 중요한지 / 왜 문제인지 / 무엇을 해야 하는지"만 설명.

### 화면 ④ Opportunity Finder — "TS가 찾은 돈" (대표 기능)
- 절세 기회 카드: 대상 매입액 → 예상 적용 가능 공제액 → 적용 가능성(높음/확인 필요/증빙자료 확인 필요) → "왜 받을 수 있나요?" 상세
- **기준 근접 알림**: 조건에 근접했을 때 "얼마 더 쓰세요"라고 단순 권유하지 않고, 반드시 경제성 분석까지 계산:
  - 추가 필요 지출 / 추가 절세 효과 / 순효과 → TS 판단(❌ 권장하지 않음 / 💡 예정 지출이면 시기 조정 검토 가치)
- 절세 ≠ 무조건 좋은 것. TS는 순효과 기준으로 판단한다.

### 화면 ⑤ Action Simulator
- 카드 3개: 인건비 5% 절감 / 객단가 3% 상승 / 원재료비 3% 절감 → 각각 예상 월 순이익 변화
- AI 추천 1줄 (순이익 개선 효과가 가장 큰 방안)
- 슬라이더로 실시간 재계산 (두 번째 WOW 포인트)

## 3. Opportunity Finder 룰 — 첫 버전은 딱 2~3개만 (P0)

### A. 면세농산물 등 의제매입세액공제
- 음식점 데모에 가장 잘 맞음. 필요 데이터: 업종/개인·법인/과세유형/과세표준/농축수산물 매입액/증빙 여부/분석 과세기간
- 대상 원재료·공제율·공제액 계산 한도·증빙 요건까지 Rule Engine이 판정
- **✅ 백엔드에 이미 구현됨** — `backend/app/engine/tax_engine_kr.py`의 `compute_vat_general()` + `backend/app/engine/official_tables_kr.py`의 `DEEMED_INPUT_RULES_2026`. 다만 "기준 근접 알림 + 경제성 분석" UI/로직은 아직 없음.

### B. 신용카드·현금영수증 발행 세액공제
- POS 연동성 좋음. 2026년 현행: 공제율 1.3%, 연간 한도 1,000만원 (2026.12.31까지), 법인 여부·매출 규모 등 제외조건 Rule Engine이 먼저 판정.
- 카드매출 → 대상 여부 판단 → 예상 공제액 → 이미 반영한 금액 → 추가로 받을 수 있는 예상 금액
- **❌ 백엔드 미구현** — 신규 Rule 추가 필요.

### C. 일반 경영 임계점 (세법 아님, 데모 효과 좋음)
- 예: "월 손익분기점까지 매출 180만원 부족", "객단가 350원 올리면 손익분기점 도달"
- **❌ 미구현** — Financial Engine 확장 필요.

## 4. 기술 구조

```
POS / 매입 Excel
      ↓
Data Normalizer
      ↓
Financial Engine (매출·비용·손익 계산)
      ↓
Opportunity Rule Engine (세법·공제·임계점 판정)
      ↓
Scenario Engine (변화 시 금액 재계산)
      ↓
AI (우선순위 선정 / 원인 설명 / 행동 제안 — 계산 금지)
      ↓
TS Dashboard
```

## 5. 법령 신뢰성 표시 (필수)

모든 Opportunity 카드 아래:
- 근거 (예: 부가가치세법 제42조)
- 기준일 (예: 2026.09.07 기준)
- 판정 (적용 가능성 높음 / 확인 필요 / 증빙자료 확인 필요)
- 디스클레이머: "TS의 계산은 입력정보를 기반으로 한 예상치이며 실제 신고 전 최신 법령 및 세무전문가 확인이 필요합니다."

Rule 데이터 모델 (세법 개정에도 코드 전체를 뜯지 않도록):
`rule_id, rule_name, effective_from, effective_to, eligibility, threshold, formula, limit, required_evidence, source_url, updated_at`

> 참고: 현재 `official_tables_kr.py`의 룰들은 이 스키마를 아직 안 씀 (dataclass 상수 형태). Opportunity Finder 구현 시 이 메타데이터 스키마로 감싸야 함.
