# TS 세금 계산 근거자료

이 문서는 TS(tax secretary)의 세금/보험료 계산 엔진(`backend/app/engine/`)이 사용하는
모든 수치(세율·기준금액·요율)의 법적 근거와 출처를 한곳에 정리한 것입니다.
값이 바뀔 때마다(고시 개정, 요율 조정 등) 이 문서도 함께 갱신하세요.

원본 고시 문서(HWP/HWPX 원문 및 law.go.kr 원문재구성본)는
[`원문/`](원문/) 폴더에 보관되어 있습니다 ([`원문/README.md`](원문/README.md) 참고).

마지막 전수 검증일: 2026-09-14 (이 세션에서 사실관계 감사 및 수정 완료)

## 1. 부가가치세 (VAT)

### 1-1. 간이과세 판정 기준액
| 항목 | 값 | 근거 |
|---|---|---|
| 간이과세 적용 상한 (공급대가, VAT 포함) | **104,000,000원** | 부가가치세법 시행령 제109조 |
| 납부의무 면제 기준 (공급대가, VAT 포함) | **48,000,000원** | 부가가치세법 시행령 제109조의2 |

- 코드 위치: `backend/data/official/vat_simple_thresholds.csv` (`annual_sales_upper_vat_included=104000000`,
  `annual_sales_vat_exempt_upper_vat_included=48000000`) → `official_db_kr.get_simple_threshold()`
- **이 세션에서 수정한 사실관계 오류**: 기존 코드는 140,000,000원으로 잘못 기재되어 있었음
  (구 기준 또는 오기로 추정). 올바른 값은 104,000,000원.
- 판정 로직의 별도 버그: `_tax_base_band_from_annual_sales()`가 "공급대가(VAT포함)"와
  "과세표준(VAT제외)"을 혼동해 1억/2억을 기준으로 비교하던 것을, VAT 포함 등가액인
  1억1천만원/2억2천만원 기준으로 수정함 (`tax_engine_kr.py`).

### 1-2. 간이과세자 실효세율
| 항목 | 값 | 근거 | 신뢰도 |
|---|---|---|---|
| 음식점업 간이과세 실효세율 | **1.5%** (업종별 부가가치율 15% 가정 × 10%) | 부가가치세법 제63조(업종별 부가가치율), 음식점업 부가가치율 15% | 중간 — 업종별 부가가치율은 매년 고시로 달라질 수 있음(현재 코드는 15% 고정 가정) |

- 코드 위치: `tax_engine_kr.py:220` (`simple_effective_rate = 0.015`)
- 한계: 실제로는 국세청이 매년 업종별부가가치율을 고시하며, 음식점업 내에서도 세분류에 따라
  다를 수 있음. 현재는 단일 고정값 사용 — 추후 업종별 세분화 고시 반영 필요.

### 1-3. 간이과세 배제지역
- 근거: **국세청고시 제2026-19호 (2026-07-01 시행)**, 별표4 지역기준
- 데이터: `backend/data/official/simple_excluded_areas.csv` (447행, v3)
- 출처: `https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulId=21174`
  (law.go.kr 행정규칙 뷰어의 페이지별 좌표 텍스트레이어를 직접 파싱해 재구성)
- 조회 로직: `official_db_kr.is_simple_excluded_area(city, district, dong, effective_date)`
  — 시/군/구/동 3개가 모두 일치해야 배제 판정
- **한계 (CSV note 필드에도 명시됨)**:
  - 원 고시는 업종·면적 조건부 배제(예: "사업장면적 33㎡ 이상 음식업자만 배제")가 많으나,
    현재 데이터는 단순화하여 지역 전체를 배제 처리함 — 실제보다 배제 범위가 넓게 잡힐 수 있음
  - 자동 좌표 추출 특성상 일부 지역이 누락되었을 가능성 있음
  - 이전 버전(v1: 2024-11-19 시행 제2024-35호 756행, v2: 2026-01-01 시행 765행)은
    더 이상 사용되지 않지만 `원문/`에 원본 보관 중
- **이 세션에서 발견·수정한 치명적 버그**: `decide_taxpayer_type()`의 `effective_date`
  매개변수가 `"2026-01-01"`로 하드코딩되어 있었음. `main.py`가 이 값을 명시적으로 넘기지
  않으므로, 이후 갱신된 고시(예: 2026-07-01 시행분)를 CSV에 넣어도 SQL의
  `WHERE effective_from <= :d` 조건에서 계속 무시되는 상태였음. `effective_date=None`을
  기본값으로 바꾸고, 미지정 시 `date.today()`를 사용하도록 수정 (`tax_engine_kr.py`).

  폴백 테이블 `official_tables_kr.py`의 `InsuranceTable2026`
- 계산 로직: `tax_engine_kr.compute_insurance_employer_estimate()`

### 이 세션에서 수정한 사실관계 오류
- **국민연금 기준소득월액**: 하한 400,000원 → 410,000원, 상한 6,370,000원 → 6,590,000원으로 수정
- **장기요양보험**: 기존 코드에 항목 자체가 누락되어 있었음(사업주 부담 총액 계산에서
  빠져 있던 잠재 버그). `LONGTERM` 항목을 신규 추가하고 `compute_insurance_employer_estimate()`에
  `longterm_employer` 계산 블록을 신설, 총 사업주 부담(`total_employer`)에 합산되도록 수정
- **고용보험 사업주 부담률**: 1.8% → 1.15%로 수정 (기존 값은 150인 이상 대규모 사업장 기준
  또는 오래된 요율로 추정)
- **산재보험 요율**: 0.95% → 0.86%로 수정 (신뢰도: 중간 — 업종 평균값이며, 실제로는 사업장별
  개별실적요율이 적용될 수 있어 참고값 성격이 강함)

## 5. 계산 파이프라인 구조 메모 (사실관계 감사 중 확인된 구조적 이슈)

- **V1 파이프라인** (`/api/v1/calc/run`, `/api/v1/calc/run-guest`): `tax_engine_kr.py`의
  `decide_taxpayer_type`/`compute_vat_simple`/`compute_vat_general`을 올바르게 분기 호출 —
  세금신고 탭에서 사용.
- **V2 파이프라인** (`/api/v2/analyze`, `/api/v2/sample`): `ts_pipeline.run_full_analysis()` →
  `dashboard_extras.build_tax_brief()` — 절세도우미 탭·홈 대시보드 KPI에서 사용.
  - **이 세션에서 발견·수정한 버그**: `build_tax_brief()`가 간이/일반 분기 없이 자체
    `_vat_portion()` 헬퍼로 VAT를 단순 추정하고 있었음. `decide_taxpayer_type`을 import해
    올바르게 분기하도록 재작성하고, `_vat_portion()`은 제거함.
  - 검증 사례: 연매출 1.2억(간이과세 상한 초과, 배제지역 아님) 케이스에서 수정 전
    "간이과세로 오판정 + 월 약 150,000원"으로 계산되던 것이, 수정 후 "일반과세로 정상
    판정 + 월 739,783원"으로 정정됨을 curl 직접 호출로 확인.

## 6. 갱신 절차 체크리스트

새 고시/요율이 나올 때마다:
1. 국세청(`nts.go.kr`) 또는 관계기관(국민연금공단/건강보험공단/근로복지공단) 고시 확인
2. 해당 CSV(`backend/data/official/*.csv`)에 새 행 추가 (기존 행 삭제 불필요 —
   `_upsert_many()`가 `effective_from` 기준으로 최신 값을 반영)
3. `python backend/init_db.py` 로컬 재실행 → `local_dev.db` 재생성 확인
4. 원본 문서를 `backend/data/official/근거자료/원문/`에 보관하고 이 문서(`TS_근거자료.md`)의
   해당 섹션을 갱신
5. curl로 대표 케이스 계산해 값이 기대대로 바뀌는지 확인 후 커밋
